# PulseBar 2.9.1

面向 13 英寸 M2 MacBook Pro 的原生 Touch Bar 监控应用。总览及二级页面保持 620 × 30 pt，保留系统控制区；Codex 位于最左侧，宽度 184 pt；温度与 CPU 各 60 pt；天气 124 pt；电池 176 pt；模块间距 4 pt。

## 本次更新

- Touch Bar 总览删除内存占用模块，天气从 60 pt 扩展至 124 pt，正好吸收原内存模块及一处间距；总宽仍为 620 pt。桌面面板的内存监测和现有二级页面实现不变。
- 天气左侧保留当前位置、天气图标和气温；文字区固定为两行 10 pt 粗体。第一行只显示当前天气状况，第二行只显示穿衣建议。总览不再显示下一小时降雨、带伞、日出日落或其他提醒。
- 两行文字由固定规则在本机生成，相同输入始终得到相同结果，不使用随机数或联网模型。天气状况直接对应当前 WMO 天气代码；穿衣档位使用当前体感温度，数据缺失时明确显示待更新。
- 动态天气底板保留高对比蓝天、旋转太阳、夜间星月、漂移云层、雾带、雨丝、雪点和雷电。两行文字不再绘制黑色玻璃衬底或黑色投影，直接融入天气画面；晴天、阴雾和雪天等明亮背景自动使用深蓝灰字，夜间、雨天和雷雨使用白字。动画约每 0.14 秒更新，只在天气模块可见且有天气数据时运行，并遵守系统「减弱动态效果」。
- 天气模块外沿不再使用白色描边，改为从当前天气渐变主色生成的深色边缘，与晴、阴、雨雪等底板自然融合。文字衬底及两行描述整体右移 3 pt，地区名称右移 2 pt，为左侧图标和气温留出更舒展的空间。
- 删除电池模块左侧的固定电池图标，将 176 pt 圆角模块本身作为电池。淡灰色表示未充部分，绿色液面严格按系统当前电量从左侧填充；充电时水流向右推进，离电时像潮水一样向左退去。
- 电池状态移到左侧，以 8.4 pt 半粗体分两行完整显示；电量百分比放大为 18 pt 粗体并位于模块正中心；预计时间继续在右侧显示。三列各自独立，`100%`、状态文字和最长时间均不会重叠。
- 百分比使用字体实际字形边界计算绘制原点，在中间区域同时左右和上下居中。恢复状态改为自绘闪电符号，Touch Bar 与桌面面板均使用矢量路径，不调用 Emoji 字形。
- 电池动画约每 0.10 秒更新一帧，完整流动周期约 5.6 秒；宽幅微光、五条弯曲水纹和液面边缘共同形成连续而缓慢的流动。动画只在模块可见且充电或放电时运行；静态供电、移出窗口或系统开启「减弱动态效果」时停止。
- 修复拔电后系统电流缓存暂时为零，导致续航显示「功率不足」的问题。M2 优先通过已有 AppleSMC 连接直接读取有符号电池功率，每五秒更新；接口不可用时回退到系统电流读数。没有新增后台定时器或管理员辅助程序。
- 对同一供电状态下短暂缺失的功率，最多沿用十五秒内的有效平均值；超时显示「采样中」。插拔、休眠及功率方向反转立即清除旧状态，不会在离电后继续显示恢复标志。
- 电源与充电标志取自同一份系统快照，物理离电时清除滞后的充电标志；瞬时电流不可用时可使用方向一致的平均电流。

## 电池显示

- 电池为 176 pt，仍短于 184 pt 的 Codex；温度和 CPU 保持 60 pt，天气扩展为 124 pt。整条宽度 620 pt，经本机 Touch Bar 可见范围检查。
- 整个电池模块用绿色与淡灰色的分界直接表示当前电量；波动边缘最多偏移约 1.5 pt，只用于呈现液体质感，不修改或推测百分比。左侧是两行电源状态，中间是放大的百分比，右侧是预计时间。
- 离开电源：显示按电池实际剩余容量与近期放电功率算出的预计续航，例如 `3H25m`。
- 接入电源并充电：显示预计充到系统显示 80% 所需时间，格式相同。
- 接电且电量达到 80%：显示自绘闪电符号，小字「电量已经恢复」。这是达到用户指定目标的状态标识，并非无限续航或改变系统充电上限。拔掉电源后切回预计续航。
- 暂未开始充电、功率接近零或数据缺失时，显示相应状态，不用假时间代替。

## 时间如何计算

只读电池原始当前容量、满充容量（mAh）、当前电压（mV），并优先读取 AppleSMC 的电池净功率；直接功率不可用时使用有符号电流（mA）。不采用系统已经算好的剩余时间，也不把适配器功率当成流入电池的功率。

- 电量（Wh）≈ 容量（mAh）× 电压（mV）÷ 1,000,000。
- 电池净功率（W）优先使用 `B0AP` 的有符号毫瓦值 ÷ 1,000；回退公式为电流（mA）× 电压（mV）÷ 1,000,000。正值为充电、负值为放电。
- 续航小时数 = 剩余 Wh ÷ 近期平均放电 W。
- 充至 80% 小时数 ≈ 满充 Wh ×（80 − 系统显示百分比）÷ 100 ÷ 近期平均净充电 W。

系统显示百分比与原始容量比存在校准差，因此 80% 目标以用户看到的百分比为准。功率使用时间常数为三十秒的指数平滑，时间向上取整到分钟，极长估计显示 `99H+`。插拔、睡眠、容量异常或方向反转重置旧估算；同一状态下的零功率或缺测仅保留最多十五秒。

这些是依据当前状态持续更新的估计；未来负载、温度、电池电压和充电末段功率变化都会影响实际时间。原始容量与电流字段参考 [Apple 电池驱动](https://github.com/apple-oss-distributions/PowerManagement/blob/main/AppleSmartBatteryManager/AppleSmartBattery.cpp) 和 [Stats 的读取实现](https://github.com/exelban/stats/blob/master/Modules/Battery/readers.swift)。`B0AP` 键与单位参考 [Linux 的 Apple Silicon 电源驱动](https://github.com/torvalds/linux/blob/master/drivers/power/supply/macsmc-power.c)，并在本机验证字节序和放电符号。

## 延续功能

- 进入和返回二级页面使用 0.2 秒淡入淡出与轻微平移动画；快速连续点击以最后一次选择为准。系统开启「减弱动态效果」时直接切换。
- CPU 温度、CPU 占用、内存曲线右侧统一显示「采样时间三分钟」。与上一次有效采样相比，上升为红色向上三角，下降为绿色向下三角，持平或数据不足时显示灰色横线。传感器暂不可读时清除旧曲线，避免显示过期趋势。
- 电量没有二级页面和省电开关，直接在总览显示详细充放电状态、电量百分比、动态充放电指示和预计时间。
- 天气全自动跟随系统位置，每五分钟安排一次更新；每次取得的新天气会立即更新天气状况、穿衣建议和动态底板，无需手动定位、选城市或点击刷新。若 macOS 尚未授权定位，需要完成系统本身的首次授权。

## 使用

将 PulseBar.app 放到「应用程序」并打开。首次运行自动配置登录启动；系统若要求批准登录项，请在系统设置中允许。关闭面板后，Touch Bar 与菜单栏继续运行。菜单栏的波形图标可打开面板、收起或重新显示监控条。

点击 Codex、CPU 温度、CPU 占用或天气模块进入二级页面，左侧箭头返回。天气二级页面仍显示当前位置、下一小时降雨概率和日出日落时间。桌面面板的 Touch Bar 预览使用相同的原生控件和动画；桌面内存卡与原有内存详情逻辑保持不变。

CPU、内存、温度每两秒读取一次，电池每五秒单独读取。CPU、内存和温度曲线最多保留 90 个采样点，睡眠或采样失败时清空；启动初期会逐步积累，因此「三分钟」是保留窗口而不是已经取得三分钟的数据。温度是有效 CPU 传感器中的最高值，非外壳温度；CPU 按全部核心归一化至 0–100%；内存统计与活动监视器可能略有差异。

## 自动天气与功耗控制

每个五分钟周期先查看 CoreLocation 的系统位置缓存，只有位置需要更新时才发起一次公里精度定位，最多等待 15 秒。定位完成即停止；失败自动退避重试，不连续开启定位。macOS 授予定位后即可自动更新。

天气刷新与定位获取分开处理：临时拿不到新位置时，可使用 30 分钟以内、来源明确的系统粗定位继续刷新天气，并显示「位置待确认」；历史手选城市不会被当作当前位置。最近的系统粗定位和时间保存在本机，重启后不必一律等待全新定位。超过有效期或没有可用系统位置时保留明确标注的旧天气缓存。

网络恢复、定位权限变更、应用激活及电脑唤醒会触发相应恢复检查；同类请求不并发。天气定时器允许系统合并唤醒，故五分钟是调度间隔，实际执行受休眠、网络和系统容差影响。地区名称单独缓存和更新。

提高天气查询频率会增加少量网络活动，不能承诺硬件功耗完全不变。实现使用按需定位、短时请求、缓存、退避、定时器容差和休眠暂停来限制额外开销，没有高频位置轮询。动态底板只在天气模块挂载可见时以低帧率本地绘制，离开窗口、数据缺失或启用「减弱动态效果」时立即停止。

Mac 的定位由 macOS 根据周边 Wi-Fi 等条件提供；软件不能绕过系统权限，也不能保证系统始终返回位置。已授权后不需要手动点击定位或刷新。

## Codex 与隐私

Codex 按 QuotaStrip 1.1.1 的显示方式保留图标、两行用量条和颜色阈值，不含 Claude。每五秒检查本机 `~/.codex/sessions` 的额度事件，常规文件发现每 30 秒一次；「立即刷新」立即重新扫描本地文件。进度表示已用额度，窗口以日志实际报告为准。过期额度显示「—」，不猜测已经归零。

**本地刷新不会主动查询 Codex 服务器。** 日志中的额度更新后，PulseBar 才能显示新值。详情区分「记录时间」和「读取时间」。只解析并保留额度元数据，不读取 `auth.json`、钥匙串或 API Key，不保存或上传会话正文。

仅天气及其系统定位、地名解析联网：将四舍五入到小数点后两位的约公里精度坐标发送到 Open-Meteo，使用 Apple 的系统定位及地理编码服务获取位置和地区名。其余指标、曲线、动画、电池状态和 Codex 处理均在本机运行，没有遥测或分析追踪。

电池充电状态来自 IOPowerSources 与系统电池驱动。限充识别参考 [OpenDente 对系统限充标记的记录](https://github.com/killerk3emstar/OpenDente#apples-native-charge-limit-macos-264)，并只读当前开机有效的系统充电策略来取得上限。没有修改充电策略或安装管理员辅助程序；字段不支持或不可读时显示一般状态，不编造上限。

天气数据：[Open-Meteo](https://open-meteo.com/)，许可 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)。

## 构建与检查

需要 Apple Command Line Tools，无第三方运行时依赖。目标 arm64、macOS 13 或更新版本；实机为 Mac14,7 / Apple M2 / 8 GB / macOS 26.4。

```sh
./build.sh                       # 在源码目录上一级生成 PulseBar.app
./build.sh /目标/PulseBar.app
./test.sh                        # 天气、Codex、趋势、电池状态和采样的离线检查
./test-layout.sh                 # macOS 图形会话中的原生控件离屏布局检查
./test-transitions.sh            # 页面动画、快速切换及资源释放检查
./test-battery-power.sh --live    # 本机电池数据与当前时间估算；加 --watch 连续观察两分钟
../PulseBar.app/Contents/MacOS/PulseBar --diagnose
```

详细验证结果见 [验证记录](验证记录.md)。Touch Bar 常驻和温度采集依赖非公开系统接口，未来 macOS 更新可能需要适配。应用采用本地临时签名，无 Developer ID 公证；重新编译或迁移机器后，系统可能重新要求授权，无需关闭安全保护。
